# lyrics_videos

Lyric videos in Remotion. Drop a song and its timed transcription into a folder, get a previewable
composition, render it whenever you want. Built to be driven by Claude Code via the
`make-lyrics-video` skill.

**Requirements:** every project needs both

- **a song or recording**: length, beats and energy all come from it
- **`lyrics.json`, a timed transcription** of that audio: plain lyrics without timings won't work

`prepare` fails without them. This workspace is only for audio-first lyric videos. Videos that
aren't driven by a song need a different setup.

```
projects/<slug>/
  input/            what you provide (never edited by tooling)
    song.mp3        required: any audio file
    lyrics.json     required: timed transcription, lines in seconds (see below)
    project.json    optional: { title, artist, audio, sections }
    brief.md        optional: mood, palette, references
    *.png, *.mp4    optional: anything else, listed in manifest.assets
  analysis/         generated by analyze: stems, beat grid, envelopes, onsets, aligned words, QA plots
  manifest.json     generated by prepare: duration, beats, energy, lyrics, sections
  storyboard.md     the plan: section → scenes
  derived/          generated by derive-media: frame-ready crops and clips (from video/media.json)
  video/
    index.tsx       defineProject({ id: '<slug>', fps, width, height, layers })
    media.json      optional: images/clips to crop and transcode into derived/
    scenes/*.tsx    one scene per file
src/
  Root.tsx          discovers every projects/*/video/index.tsx (skips "_" folders)
  kit/              contract, hooks, timeline renderer, manifest schema
analysis/           Python (uv): stems, beat grid, CTC word alignment (see analysis/README.md)
scripts/            prepare, derive-media, stills, render
out/<slug>/         renders and stills (gitignored)
```

## Commands

From the repo root:

```bash
npm run analyze -w lyrics_videos -- <slug>          # stems, beat grid, aligned words → analysis/
npm run prepare-project -w lyrics_videos -- <slug>  # input/ (+ analysis/) → manifest.json
npm run derive-media -w lyrics_videos -- <slug>     # video/media.json → derived/ (16:9 crops, clips)
npm run studio -w lyrics_videos                     # preview every project
npm run stills -w lyrics_videos -- <slug>           # one JPEG per section, for a quick check
npm run stills -w lyrics_videos -- <slug> 12.5,40 --only   # just these seconds
npm run render-project -w lyrics_videos -- <slug>   # full MP4 into out/<slug>/<slug>.mp4 (+ <slug>.map.json)
npm run render-project -w lyrics_videos -- <slug> --proxy   # the same at half size: a review render
npm run map -w lyrics_videos -- <slug> --video=<mp4>  # shot map for any other render
npm run preflight -w lyrics_videos -- <slug>        # machine checks before the user reviews a render
npm run wait-revision -w lyrics_videos -- <slug>    # wait until a revision is set to "Ready for Claude"
npm run look-grid -w lyrics_videos -- <a.mp4> <b.mp4> …   # 2–4 look previews side by side, labelled
npm run loop-stats -w lyrics_videos                 # rounds, notes and renders per video, from the review files
npm run cleanup-out -w lyrics_videos -- scan       # what fills the disk; clean, archive to a hard disk, restore (cleanup-out skill)
npm run type-check -w lyrics_videos
```

## Render

`render-project` needs a manifest (`prepare-project` first). The composition id is the slug.
Anything after the slug is passed through to `remotion render`. Output is
`apps/lyrics_videos/out/<slug>/<slug>.mp4`. A full render takes minutes.

Each render also writes `<slug>.map.json` beside the MP4: every shot from
`projects/<slug>/video/shots.json` with its ID and time range (one shot per lyric line when the
project has no shot list). mediamake's Video Revision screen (`/video-revision`) reads it to tag review
comments with shot IDs, and saves the comments in `<slug>.revisions/` next to the video.

```bash
# whole song
npm run render-project -w lyrics_videos -- <slug>

# a slice, to check motion. --frames is frame numbers at the project's fps
# (0-299 is the first 10s at 30fps). --proxy renders at half resolution (--scale=0.5).
npm run render-project -w lyrics_videos -- <slug> --frames=0-299 --proxy

# a review render: the whole song at half size into the same file (same review link and map);
# render the master without --proxy once the user signs off
npm run render-project -w lyrics_videos -- <slug> --proxy

# a look preview: { "look": "B" } as input props, into out/<slug>/looks/B.mp4
npm run render-project -w lyrics_videos -- <slug> --look=B --frames=0-239 --proxy

# higher quality (lower CRF; Remotion's default is 18)
npm run render-project -w lyrics_videos -- <slug> --crf=16
```

Other flags pass through too (`--concurrency`, `--image-format=png`).
The full list is at https://www.remotion.dev/docs/cli/render. Every render is logged in
`out/<slug>/.renders.jsonl` (when, which file, scale, seconds).

### On Lambda

`--lambda` renders the same thing on Remotion Lambda through mediamake's AWS setup
(`apps/mediamake/config.mjs`: the bucket, the regions, the function presets; the keys in
`apps/mediamake/.env` as `REMOTION_AWS_*`), into the same files, and prints what it cost.
Lambda renders are billed, so check the plan first and start with a short window.

```bash
# the routing plan alone: what would go up, which way it leans and why (nothing is spent)
npm run lambda -w lyrics_videos -- plan <slug>

# a 20 s stretch (song seconds) → out/<slug>/clips/<slug>-<a>-<b>.mp4, with the cost and an estimate for the whole video
npm run render-project -w lyrics_videos -- <slug> --lambda --window=10-30

# the whole video (the previous render kept in v<N>/), at half size for a review, or a look
npm run render-project -w lyrics_videos -- <slug> --lambda
npm run render-project -w lyrics_videos -- <slug> --lambda --proxy
npm run render-project -w lyrics_videos -- <slug> --lambda --look=B --window=0-8

# a short, another region or function preset, or the site as it was last deployed (no bundle, no upload)
npm run render-project -w lyrics_videos -- <slug> --short=s01 --lambda
npm run render-project -w lyrics_videos -- <slug> --lambda --region=us-east-1 --preset=basic-fast
npm run render-project -w lyrics_videos -- <slug> --lambda --skip-deploy

# deploy the site without rendering; what is deployed in the region
npm run lambda -w lyrics_videos -- deploy <slug>
npm run lambda -w lyrics_videos -- sites
npm run lambda -w lyrics_videos -- functions
```

How it works (`scripts/lambda.ts`): the project is bundled alone (`ONLY_PROJECT`) and uploaded as
its own site, `lyrics-<slug>` (`lyrics-<slug>-<region>` outside the default region), next to the
app's `mediamake` site. Its inputs travel as that site's public folder: exactly the files the
project needs are cloned (APFS, no space taken) into `out/<slug>/.lambda/public/<slug>/` (the
manifest, `video/edits.json`, the song, every file `assets` names, every file edits.json swaps in,
`fonts/`, `derived/`, any `'<slug>/…'` path written in the code), so on Lambda
`staticFile('<slug>/input/x.png')` finds the same file and the manifest goes in as inputProps
unchanged, swaps and all. `deploySite` compares the bucket by content, so a second deploy uploads
only what changed (the bundle after a code change, not the inputs). Scenes must load files through
`asset()` or the manifest; a `staticFile()` of a path outside `projects/<slug>/` has nothing to find
on the site. `--window`, `--region`, `--preset` and `--skip-deploy` are the Lambda path's own flags;
`--frames`, `--proxy`/`--scale`, `--look` and `--crf` apply as locally; other `remotion render`
flags don't.

The cost printed is Lambda compute as Remotion accounts it (S3 storage and transfer come on top);
the `.renders.jsonl` line keeps it (`lambda.costUsd`). Before anything is spent, the routing plan
(`apps/mediamake/docs/render-routing.md`) weighs the project's media against the heavy limits and
says which way it leans and why: the song plays all along, a clip the code names counts as playing
all along (overlays loop under everything), images are reported but not counted. A heavy project
still renders when asked (`--lambda` is the pick), with the reason shown; every Lambda chunk
downloads the clips it touches in full, so a video with long overlay clips costs more there than on
this machine.

## Review loop

The `revise-video` skill drives it; these scripts are its parts.

- **`preflight <slug>`** checks a render before the user sees it: black and frozen frames, a missing
  or short sound track, dropouts, clipping, a quiet master, and with `--source=<picture>` a render
  darker or duller than the user's picture. Findings become machine notes ("Preflight · …") that open
  the video's next revision in `<slug>.revisions/`; a rerun closes what is gone, and
  `--intended=<id> --why="…"` answers one that is meant. `--video=<mp4>` for any other render.
- **`wait-revision <slug>`** exits when the user sets a revision under `out/<slug>/` to "Ready for
  Claude" and prints its open notes. Claude runs it in the background after giving the review link.
- **`look-grid`** puts 2–4 look previews of the same stretch into one grid video, each tile labelled
  with its look ID, so the user picks by name in the Revisions screen. `wave-lab … --clip` makes one
  too.
- **`loop-stats [slug …]`** reads every `.revisions/` folder, the kept `v<N>/` versions and the render
  log: rounds and notes per video, and render minutes per production.

To render through mediamake's render API or Lambda, pass `inputProps = { manifest }`
with asset paths rewritten to public URLs.

## How a project is put together

Layers place scenes on the timeline. `at` is a manifest section label, `'all'`, or `{ from, to }` in seconds:

```tsx
export default defineProject({
  id: 'sample-pulse',
  fps: 30,
  width: 1920,
  height: 1080,
  layers: [
    layer({ scene: Backdrop, at: 'all' }),
    layer({ scene: KineticLyrics, at: 'verse-1', props: { accent: '#7cccff' } }),
  ],
});
```

Scenes are `React.FC<SceneProps<P>>` and get `manifest` and `section` as props. Kit hooks work in
absolute song time: `useSongTime`, `useSection`, `useLyrics`, `useBeat`, `useBar`, `useEnvelope`,
`useHit`, `useEnergy`, `asset`. Pure helpers in `src/kit/timing.ts` find lines by content
(`findLine`) and move on the grid (`beatAt`, `timeOfBar`, `cutBefore`, ...).

The composition loads `projects/<slug>/manifest.json` through `calculateMetadata`, and the duration
comes from the audio.

## mediamake presets (vertical-float lyrics, waveforms)

`src/mediamake` runs mediamake's own editor presets inside a project: `VerticalFloatLyrics`
(the `sub-vertical-float` caption preset), `WaveformLayer` (spectrum fill/line with the Wave Look
looks, or the `waveform-audio` preset), `CoverBackdrop` and `TrackTitle`, plus the `lyricVideo()` and
`waveformVideo()` templates. A project can then be a few lines:

```tsx
import { lyricVideo } from '../../../src/mediamake';
export default lyricVideo({ id: 'my-song', cover: 'cover.jpg', lyrics: 'default', wave: 'default' });
```

See `src/mediamake/README.md`. After a preset changes in apps/mediamake, run
`npm run sync-presets -w lyrics_videos`.

Waveform lyric videos (a song and a picture in; the `make-waveform-lyric-video` skill) are a
`video/storyboard.ts` of three choices — wave, font set, caption animation — picked from
`catalog/` (see `catalog/README.md`) or designed for the song.
`npm run wave-lab -w lyrics_videos -- <slug> <waves|fonts|captions|final>` shoots the candidates on
the project's own song and picture; `-- catalog` shoots every catalog entry into `out/waveform-catalog/`.

## Remix projects (footage cut to a song)

A project with `video/edl.ts` is a music remix: existing footage cut to the song on its beat grid at
its own speed, joined by transitions (warp zooms anchored on the subject, match cuts, whips, spins,
subject cutouts carried over the next shot), with camera shake, wide-tracked lyric lines, punch
words behind the subject, motion graphics (`src/remix/gfx/`, three.js) and a few sound effects.
The engine is `src/remix/`; the footage's shots come from an analyze-video run in
`projects/<slug>/footage/`.

```bash
npm run remix -w lyrics_videos -- <slug>           # footage table, plates, anchors, resolve + check the cut list, shots.json
npm run remix -w lyrics_videos -- <slug> --matte   # + subject cutouts per footage shot (scripts/matte.py, BiRefNet via uv)
```

Configured by `projects/<slug>/video/remix.json` (`source`, `segregation`, `crop`, `window`). Driven by
the `make-video-music-remix` skill; `projects/hitixf1` is the reference.

### Shorts (vertical cuts of a remix)

`projects/<slug>/shorts/<id>/` is a vertical short of one stretch of the song: `short.json` (the
window, the formats), `edl.ts` (its cut list in the song's beats, usually starting from the long
edit's) and `index.tsx` (`defineShorts`, one composition per format: `<slug>-<id>-9x16`, `-3x4`,
`-4x5`). In a vertical frame `Remix` reframes each cut around its subject; `band()` and stacked
`split`s keep the wide picture sharp. Driven by the `make-video-music-remix-shorts` skill.

```bash
npm run shorts -w lyrics_videos -- <slug> pick                          # the three coolest stretches + alternates (mp3s, picks.png)
npm run shorts -w lyrics_videos -- <slug> make A,B,C --formats=9x16,3x4 # scaffold the approved ones
npm run shorts -w lyrics_videos -- <slug> mark C bad                    # never pick that stretch again
npm run remix -w lyrics_videos -- <slug> --short=s01                    # check the short's window
npm run stills -w lyrics_videos -- <slug> 0.2,5 --only --short=s01 --format=9x16
npm run render-project -w lyrics_videos -- <slug> --short=s01           # → out/<slug>/shorts/s01/<slug>-s01-<format>.mp4
```

## lyrics.json

Any of these, with times in seconds from the start of the song:

```jsonc
[{ "text": "City lights are humming low", "start": 3.0, "end": 5.4 }]           // lines; words spread evenly
[{ "text": "...", "absoluteStart": 0.48, "absoluteEnd": 26.08, "words": [...] }]  // mediamake caption format
{ "lines": [...] }  /  { "captions": [...] }                                     // either one, wrapped
```

When `project.json` has no `sections`, they're derived from the lyrics: gaps over 2.5s start a new
section, a repeated block becomes `chorus-n`, everything else is `verse-n`. Gaps over 6s become
`break-n`, and the parts before and after the lyrics become `intro` / `outro`.

See `projects/sample-pulse` for a complete example. Its song is a synthetic 120 bpm track.
